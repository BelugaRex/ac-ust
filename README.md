# AC-UST ❄️

Chrome 扩展 — 自动控制 HKUST Smart Power Meter 冷气，支持 PWM 循环定时、智能天气控制与运行时段。

## 功能

- **PWM 循环定时**：自定义"开 X 分钟 / 关 Y 分钟"持续循环，自动控制冷气开关
- **运行时段**：独立约束 PWM 循环定时与智能控制。时段外只暂停自动执行并保留当前模式选择，通过页面 `Power-off after` 安全停机；进入时段后循环定时可立即恢复，智能控制仍等待下一次有效的 `HH:00`/`HH:30` 首分钟窗口。自动控制已关闭时可预先编辑时段，不会因此触发停机
- **智能控制**：按香港天文台将军澳站（JKB）的气温、相对湿度、风速与站点雨量计算每个 30 分钟周期内的开启时长；露点由同站温湿度推导，雨量从无雨到黄雨阈值按后段更陡的指数曲线增强影响，最多把开启时间减半。灵敏度滑块提供 0–10 共 11 档（更省钱←→更干冷）；后台在 `:20`/`:50` 预取并生成分别绑定下一 `:30`/`:00` 的方案，方案保留原始天气，控制边界按当前灵敏度纯本地重算，不发起或等待天气网络。若目标方案丢失或 Service Worker 在 ON 周期中途重启，会用边界前的新鲜本地天气恢复同一建议时长并保留原半点锚点。普通调用只在 `HH:00`/`HH:30` 首分钟启动；真实半点 `ac-pwm` 闹钟迟醒，或启动／看门狗发现当前理论 ON 窗口仍安全但下一次开启已错误推到下个半点时，会立即补执行本周期剩余 ON 相位。页面 timer 失败后若权威页面较晚确认 AC 已 OFF，会保留原半点所有权，并从该次 OFF 证明起满足至少 5 分钟压缩机保护后补开；安全窗口不足才跳到下一半点。关机点始终不晚于“原半点 + 建议分钟”，不会从恢复时刻重新获得完整时长；已有本周期关机闹钟或一分钟失败重试也不会被抢占。剩余时间不足以可靠写入页面保险时不会新开机。单次最多开启 25 分钟并至少关闭 5 分钟；普通 PWM 循环仍可在任意分钟切换
- **可用时刻预计**：仅在 Smart Power Meter 显示 `Charge Mode` 且自动控制处于运行时段内时，读取冷气余额并计算分钟级预计时刻；其他计费模式或时段外暂停时隐藏 est，避免误导。今明两日显示“今天／明天”，之后显示月日，预计 24 小时内用完时以轻量警示突出
- **跨设备同步**：多台设备运行扩展时自动对齐 PWM 循环；本地发布与远端采纳共享顺序屏障，失败发布以本机 marker 和独立闹钟持久重试，入站读取失败也会重试。慢时钟旧设备发出的明确停用仍具有安全优先级；页面 timer 修复只向对端投影明确的近期 OFF，不会让新设备把无相位配置误当成新一轮立即开机
- **开机完成确认**：AC 为 OFF 时，扩展先在同一个精确 home 标签预置 `Power-off after`；即使受控 picker 延迟提交或用新 DOM 节点承载结果，也必须重新定位唯一控件并连续读到目标值后，才允许一次 ON 点击。预置失败或标签漂移均零点击，预置后也禁止靠刷新接力开机。正常路径仍须等到本次新出现的 `Execution succeeded` 与 ON 状态，再用独立新鲜页确认关机保险；若开机结果含糊但同页已可读为 ON，则不再点击，只验证保险。页面原本已经 ON 时零点击且无需新 toast，直接设置并验证 `Power-off after`
- **五分钟舒适启动**：本机把自动控制由关切到开时，先从已确认 ON 的时刻保证至少五分钟冷气，再进入所选循环／智能策略；页面已经 ON 时零点击，只补设或保留更晚的 `Power-off after`。首次安装仅在采用到已启用配置时执行一次；打开 Popup、普通 Service Worker／浏览器重启和扩展更新都不会重新触发。舒适期可暂时跨越运行时段，但用户主动停用始终立即优先，并继续只用页面定时器安全关机
- **后台运行**：即使关闭弹窗，定时任务仍在 Service Worker 中执行
- **关机确认**：只复用 URL 完整等于 `https://w5.ab.ust.hk/njggt/app/home` 的标签；没有精确 home 时另建隐藏页，不改写 billing-cycle、warning、登录回调或其他 UST 页面。浮点持续时长只在写入 UST 的 `HH:MM` 接口时向上对齐为整分钟绝对截止时间，同一截止时间驱动页面值、证明、扩展闹钟与倒计时；设置后由独立新鲜页按 `10/15/20` 秒退避回读同一时间，未确认时自动重试
- **精确 home 隔离**：冷气状态读取、开机和页面定时器读写都只允许发生在精确 home URL；尾斜杠、查询串、哈希、相似路径和业务子页均拒绝作为初始操作目标。普通未预置的低层恢复仍最多刷新一次；生产 ON 在预置 timer 后不刷新、不导航、不接力点击，任何 BFCache／URL 漂移都会让整笔事务退出并在下一轮从重新预置开始。智能 ON 的原相位绝对截止已到、剩余时间无法安全设置页面保险或自动控制已暂停时直接安全终止
- **诊断面板**：先冻结诊断请求到达时的 `before` 现场，再由 Service Worker 独占执行必要修复，并分别输出 `repair` 与 `after`；不会用修复后的正常状态覆盖原始反例。报告用稳定错误码标出首要问题、所属环节、当前 PWM 尝试和上次结果，并检查 Popup 文档、尺寸、运行期异常、控件同步与后台链路。独立兜底脚本先于主脚本加载；即使 Popup 主诊断未能注册，仍可只读导出脱敏 schedule、`ac-*` alarms、heartbeat 和 SW 部分现场并一键复制，不执行自愈。正常纵向滚动不计为异常，且不会采集页面 URL、DOM 文本、账号或余额。自动控制关闭、运行时段外暂停和未启用智能控制会按预期状态说明；已触发的 `ac-pwm` 在建立下一闹钟前显示为“边界处理中”。最近 50 条脱敏后台异常仅保存在本机，运行诊断后只按新到旧附带当前构建以来最新 5 条，且历史记录不计入当前问题汇总
- **构建标识**：头栏以 `MM/DD HH:mm` 显示版本号与构建时间；正式构建还会核对 Popup、Service Worker、content script 与页面主世界脚本四方身份，发现旧接收端时在原标签页重注入并复核，不刷新页面、不自动重载扩展，仍不一致则失败关闭
- **清晰与低干扰**：固定使用与 UST 页面一致的浅色外观，提供清晰文字与语义状态反馈；切换自动模式时两个互斥选项会一起短暂锁定并显示进行中状态，完成后恢复，同时适配系统的减弱动态效果和高对比度
- **中英双语**：popup、后台与页面操作错误均支持中文/English，通过 Crowdin 社区翻译更多语言

## 0.8.2 更新要点

- 修复 HKUST 受控 `Power-off after` picker 延迟提交／替换输入节点时被过早判定为拒绝的问题；扩展现在等待唯一语义控件稳定接受目标值，持续歧义或超时仍保持零 ON 点击。
- 诊断改为不可变 `before → repair → after` 证据链，并记录当前 PWM 尝试与上次结果；Popup 不再直接写调度 storage。正式构建统一注入 Popup、Service Worker、content script 与页面主世界脚本身份，原页可安全重注入旧运行时且不会刷新用户页面。
- 修复真实智能周期在页面关机证明失败后漏开：若页面随后确认 AC 已 OFF，不再把下一 ON 直接推到下个半点；系统保留原 `:00`/`:30` 周期所有权，从新鲜 OFF 证明起完成至少 5 分钟压缩机保护后，以 typed safety retry 补执行仍安全的剩余窗口。无效的 `:00`/`:30` ON 时钟会被恢复、同步、闹钟准入和诊断共同拒绝；Popup 倒计时按下一动作相位显示，不再把“下一步 OFF”写成自动开启。
- 加固跨设备安全收敛：页面 timer-only 修复发布明确未来 OFF，相同 OFF 相位只允许收紧截止；显式停用可跨慢时钟 watermark 生效。外发 publish 与入站 adopt 共享顺序屏障，并以 durable pending marker、独立重试闹钟和重叠后的物理 store 重读，避免一次 storage 故障永久吞掉停用，或按事件到达顺序误采纳已被后续写覆盖的快照。
- 自动 ON 改为同页“先保险后开机”：锁定一个精确 home 标签，先预置 `Power-off after`，再执行唯一 ON 点击，最后才以新鲜页记录正式证明；预置歧义／页面漂移零点击，预置后不刷新。缺少新 toast 但同页实际已 ON 时不重复开机，只补验证保险。PWM、五分钟舒适启动与手动 ON 共用同一事务。
- 自动控制新增一次性的五分钟舒适启动：关→开前先保留已有更晚 timer 并预置至少五分钟保险，正常开机仍等待本次 `Execution succeeded` 与 ON 收敛；已 ON 零点击。失败保持安全相位并一分钟后重试；运行时段外先完成舒适期，用户停用仍可立即取消。首次安装以本机 marker 防止重启重复执行，Popup 打开与扩展更新零触发。
- 运行时段从循环定时设置中抽离为两种自动控制共用的独立门禁；时段外不再把用户选择伪装成“已关闭”，启动、同步、看门狗、诊断和延迟恢复也不会绕过暂停状态重建运行闹钟。天气预取与关机重试继续运行。
- 修复自动 ON 时页面进入 BFCache 导致消息端口关闭后，恢复链把仍处于 `complete` 的旧业务子页误判为已就绪的问题；现在会等待同一控制标签真正回到精确 home 并完成加载，再执行最多一次幂等重试。
- 修复智能 ON 恢复跨过首分钟后仍刷新页面并留下 `toggle-refresh-recovery` ERROR 的误报；截止或运行门禁已失效时直接停止恢复，真实连接故障仍保留一次有限恢复与诊断记录。
- 智能控制自动开启锚定 `:00`/`:30`，页面关机截止固定为“半点 + 最多 25 分钟”；普通迟到调用仍不补开，但真实半点闹钟或启动恢复会在页面保险仍可可靠写入时执行当前剩余 ON 相位，不会从处理时刻重新获得完整时长。页面已 ON 时零点击、无需新 toast，直接补设原绝对关机点。普通循环定时不受半点门禁影响。
- 修复智能模式生命周期恢复把当前 ON 周期算术快进到下个半点，导致冷气明明处于建议开启窗口却继续等待十几分钟：启动、过期闹钟与看门狗现在只在下一 ON 已越过当前截止时补执行剩余窗口，并保留原半点绝对关机点；本周期短重试、安全余量与普通迟到门禁保持不变。
- 天气改由严格未来的 `:20`/`:50` 一次性闹钟提前获取并预计算下一 `:30`/`:00`；方案保留原始天气，控制边界优先消费目标时间完全匹配的本地方案，并按当前灵敏度纯本地重算，不直接或间接联网。目标方案缺失或 ON 周期中途重启时可回退到边界前一小时内的新鲜本地观测；边界后、过期或 stale 观测不会被误用。
- 智能天气输入改为将军澳 JKB 的独立实时气温、湿度、风与站点雨量，不再混用天文台湿度、静风或西贡区雨量；降雨修正由 `>5 mm` 直接减半改为 0–30 mm/h 后段更陡的指数渐变，黄雨阈值及以上才达到最多减半。
- 智能计算的 `K`、天气观测、`Teq`、降雨修正与 `tRaw` 保留浮点精度，只在最终展示和控制值处量化分钟数。
- UST 页面关机时间、新鲜页证明、PWM planner、扩展闹钟与倒计时统一采用向上对齐到整分钟的绝对截止时间。
- 诊断报告忽略构建前、未来或非法时间戳，只按新到旧显示当前构建以来最新 5 条本机脱敏异常。
- 诊断报告新增当前问题摘要、稳定错误码、问题域、现场证据和下一步建议；预期停用／暂停状态不再显示为故障，自动修复会明确列出本次补建项目。
- Chrome Web Store 上架文案、隐私政策、提交清单与可上传图片集中在 [`商店/`](商店/README.md)。

## 安装

> 💡 **推荐：先用脚本打包到 `dist/`，再加载 dist 文件夹**，这样开发修改不会影响正在使用的扩展。

```bash
# 1. 克隆仓库
git clone https://github.com/BelugaRex/ac-ust.git
cd ac-ust

# 2. 打包到 dist/ 目录（WSL/Linux，需 Python 3）
bash ./build.sh

# 3. 打开 Chrome/Edge
#    地址栏输入 chrome://extensions 或 edge://extensions
#    开启「开发者模式」→「加载已解压的扩展」→ 选择 dist 文件夹
```

> 登录 [HKUST Power Meter](https://w5.ab.ust.hk/njggt/app/home) 即可使用。更新代码后重新运行 `bash ./build.sh`，再到扩展管理页点刷新图标即可。

> 自动化测试使用 Node.js 20；在仓库根目录执行 `nvm install && nvm use` 后，再运行 `node test/verify-fix.mjs`。

## 使用说明

| 操作 | 说明 |
|------|------|
| 自动控制 | 用独立总开关统一启停；关闭时仍可预设「循环定时 / 智能控制」模式与参数 |
| 自动模式 | 在「循环定时 / 智能控制」分段控件中二选一；分段控件只选择模式，不负责启停 |
| 开启分钟 | 每次开启冷气持续多少分钟（修改后自动重启循环） |
| 关闭分钟 | 每次关闭冷气持续多少分钟（修改后自动重启循环） |
| 运行时段 | 使用 24 小时制 `HH:mm`，独立作用于循环定时和智能控制；时段外保留所选模式并用页面定时器安全停机，重新进入后循环定时可立即恢复，智能控制等待下一次有效半点窗口 |
| 智能控制 | 在自动模式中选择后按天气计算开启时长；`:20`/`:50` 提前准备下一 `:30`/`:00` 的本地方案，边界不等待网络；方案丢失或 ON 周期中途重启时会用边界前的新鲜本地天气恢复界面所示建议时长；普通调用仅在首分钟启动，真实半点闹钟迟醒时可补执行原 ON 相位剩余部分但绝不延长原关机点；已 ON 直接补设页面 timer，OFF 始终由该 timer 执行 |
> 💡 **重要**：请将 UST AC 页面在浏览器中**固定标签页**并保持开启，否则定时开关无法控制空调。

> ⚠️ **不要同时在 Chrome 和 Edge 上使用 AC-UST**
>
> Chrome 与 Edge 的浏览器账号同步互不互通，`chrome.storage.sync` 只在同浏览器生态内有效。虽然 UST 页面定时器能跨浏览器同步「关」相位，但 **运行时段**、**开/关分钟数** 等配置无法跨浏览器同步。同时使用会导致两台设备各自跑独立 PWM 循环（配置不同步），同一台空调被反复开关。
>
> **建议**：选择一个浏览器生态（全 Chrome 或全 Edge），不要混用。同生态内多设备会自动对齐 PWM 循环。

### 方式一：通过 Crowdin（推荐）

1. 访问 [Crowdin 项目页面](https://crowdin.com/project/ac-ust) — 已连接 GitHub，修改会自动开 PR
2. 选择你的语言，在网页上对照源文本填写翻译
3. 提交后 Crowdin 会自动向 GitHub 开 PR，合并即生效

### 方式二：直接编辑 JSON 文件

1. 复制 `_locales/en/messages.json` → 改名为你的语言代码（如 `ja/`、`ko/`、`fr/`）
2. 把每个 `"message"` 的值翻译成你的语言
3. 注意：`$1`、`$2` 等是占位符，**保留不动**
4. 提交 PR 到本仓库

语言代码参见 [Chrome 支持的语言](https://developer.chrome.com/docs/webstore/i18n?hl=zh-cn#localeTable)。

## 贡献指南

> ⚠️ **不要直接向 `main` 分支提交代码。** `main` 是稳定发布分支，只接受经过充分测试的变更。

### 分支策略

| 分支 | 用途 | 说明 |
|------|------|------|
| `main` | 稳定发布版 | ❌ 禁止直接推送，仅接受来自 `beta-rex` 的合并 |
| `beta-rex` | 项目作者的开发主线 | ❌ 请勿推送，这是作者的个人开发分支 |

> 外部贡献者请 **Fork 仓库** → 在自己的 Fork 上创建分支 → 向 `beta-rex` 提 PR。

### 提交流程

```bash
# 1. Fork 本仓库（在 GitHub 页面点右上角 Fork）

# 2. Clone 你的 Fork
git clone https://github.com/你的用户名/ac-ust.git
cd ac-ust

# 3. 创建你自己的开发分支（不要用 beta-rex）
git checkout -b my-cool-feature

# 4. 开发、测试
bash ./build.sh
node test/verify-fix.mjs

# 5. 提交并推送
git add .
git commit -m "feat: 描述你的改动"
git push origin my-cool-feature

# 6. 在 GitHub 上创建 PR → 目标仓库选 BelugaRex/ac-ust，目标分支选 beta-rex
```

### 规则

- **不要直接推送到 `beta-rex` 或 `main`** — 这是作者的分支，请通过 PR 贡献
- **一个 PR 做一件事**，方便 review
- **先构建并测试再 commit**：`bash ./build.sh && node test/verify-fix.mjs`
- **翻译贡献**：其他语言通过 [Crowdin](https://crowdin.com/project/ac-ust) 或直接编辑 `_locales/` 下的 JSON 文件；`zh_CN` 与 `en` 由作者直接维护，请勿改动
- **Crowdin 自动 PR**：如果内容全是源语言（未翻译），直接关闭即可；有真正翻译时再合并；若 PR 含 `_locales/zh_CN/` 或 `_locales/en/` 改动，一律关闭不合并

## 技术栈

- Chrome Extension Manifest V3 · Vanilla JavaScript（零框架依赖）
- Chrome Alarms API + Storage API + Scripting API
- Apple Design System CSS（SF Pro / Inter 字体，扁平 UI，无毛玻璃）
- fetch-based i18n（Crowdin 社区翻译）
- 跨设备同步（chrome.storage.sync + UST 页面定时器服务器同步）
- Service Worker 保活（heartbeat + offscreen + waitUntil）

## 故障排查

- `onMinutes` / `offMinutes` 是**静态配置**，会像表单值一样持久化保存。
- 智能控制天气数据来自 **香港天文台开放数据 API**：将军澳站（Tseung Kwan O / JKB）的 1 分钟平均气温、1 分钟平均相对湿度、10 分钟平均风速，以及将军澳站过去 1 小时雨量；露点由同站气温与湿度用 Magnus 公式推导。后台使用严格未来的 one-shot 闹钟在 `:20`/`:50` 拉取并预计算下一 `:30`/`:00`，控制边界优先消费目标完全匹配且足够新鲜的本地方案。目标方案丢失或 ON 周期中途重启时，会用边界前一小时内的新鲜缓存按当前灵敏度恢复同一建议时长；边界后、过期、stale 或带错误的观测仍会被拒绝，且控制路径不等待天气网络。
- `nextTriggerAt` 是**运行时派生值**，表示当前 PWM 阶段的未来切换时刻；它会随着每一轮开/关切换而变化。
- 如果诊断里出现“`ac-pwm` 闹钟存在，但 storage 绝对触发时间缺失”，通常表示后台在创建/恢复闹钟后，`nextTriggerAt` 没有及时回写到 storage。
- 当前实现会优先以 live `ac-pwm` 的 `scheduledTime` 纠偏 `nextTriggerAt`，并在读取 AC 状态时优先询问主世界脚本，避免隔离世界把 `ON` 误读成 `OFF`。
- `Power-off after` 的本页输入值不是最终凭据：扩展会保留写入页，以隐藏的新鲜页面按 `10/15/20` 秒间隔读回相同的 `HH:MM` 后才推进到下一关机阶段。验证失败会保留安全相位并重试；浏览器重启后错过的 retry 也会重新排程，且不会刷新你正在看的 AC 页面。
- 诊断报告只会按新到旧附带本机当前构建以来最新 5 条后台异常；构建前、未来或非法时间戳记录会被忽略。环形日志仍最多保留 50 条，只含时间、级别、代码阶段和截断后的脱敏错误消息，不记录页面 URL、标签 ID、DOM、余额或账号信息，也不会进入 `chrome.storage.sync` 或上传到服务器。
- 如果后续仍复现“alarm 还在但时间丢失”，下一步应把阶段检查点（例如 `alarmCreatedAt`、`alarmDelayMinutes`、`pwmState`）进一步提升为正式真相源，由它们重算 `nextTriggerAt`。
